# Concentric Spiral / Rings — Image → SVG

How the spiral strategy turns a raster image into vector line art the way a
lathe-turned guilloché or a single-stroke pen plotter would: one line wound out
from the centre of the picture, near-circular where the image is light and
buckling inward where it is dark.

## The core idea

A smooth circle or spiral carries no tone. Deform its path and the deformation
can stand in for darkness. This strategy winds a single line out from the image
centre and encodes tone into **two** path modulations, both driven by the local
sample:

- **wiggle** — darker pixels push the path off its smooth radius (amplitude) and
  tighten the oscillation (frequency), so dark zones read as jagged, busy bands
  while light zones stay near-circular;
- **compress** — darker pixels shrink the local pitch, so successive turns pack
  closer together and lay down more line per unit area.

Where both peak, the line becomes a dense, ragged thicket that reads as solid
ink; where the image is light, it relaxes into clean, widely-spaced arcs. The eye
reassembles a continuous gradient out of the varying line density — the same
illusion that powers hatching, reached from the centre out.

## Pipeline overview

```
image ─▶ downscale + luminance ─▶ tone buffer ─▶ wound + modulated path ─▶ <svg>
        (ImageToSvgCanvas)         (StrategyInput)  (spiral.ts)
```

### 1. Image → tone buffer

Identical to every strategy: `prepareInput()` in `ImageToSvgCanvas.tsx`
downscales the image (long edge ≤ **700 px**), reduces each pixel to a Rec. 709
**luminance** in `0..1`, and exposes a **bilinear** `sample(x, y)`. The
framework-free `{ width, height, luma, sample }` is the `StrategyInput`. No image
data leaves the browser.

### 2. Tone → darkness

Each sampled value is shaped, then flipped so larger means *more ink*
(`darknessAt` in `spiral.ts`). Points outside the image return `0` (light), so
the path stays smooth where it overshoots the corners:

```ts
if (x < 0 || x > W || y < 0 || y > H) return 0;
let l = sample(x, y);
l = clamp01(0.5 + (l - 0.5) * contrast); // contrast pivots around mid-grey
if (invert) l = 1 - l;
return 1 - l;                            // darkness: 0 = light, 1 = dark
```

`darkness` in `0..1` is the single quantity that drives both modulations.

### 3. Winding outward from the centre

The path starts at the image centre `(W/2, H/2)` and is generated by **integrating
the radius outward** rather than from a closed `r = b·θ` formula — that is what
lets the pitch vary per-point. The farthest image corner sets `maxR`, where the
wind stops. The angular marching step is bounded (`~1–2.5 px` of arc, derived
from `Pitch`) so the wiggle is resolved while generation stays fast, and a hard
point cap keeps an extreme pitch from exploding the file.

### 4. The continuous spiral

At each step the smooth base point is `P = centre + r·(cos θ, sin θ)`. We sample
the darkness there, displace the plotted radius **radially** by a sine wiggle,
then advance both the angle and the radius:

```
rr      = r + amplitude · darkness · sin(phase)        // plotted radius
point   = centre + rr · (cos θ, sin θ)
Δθ      = step / max(r, step)                          // bounded near the centre
phase  += frequency · Δθ · (1 + freqMod · darkness)    // tightens in dark zones
r      += (pitch / 2π) · Δθ · max(0.1, 1 − compress · darkness)
θ      += Δθ
```

- **Amplitude** scales the radial offset by `darkness`, so light arcs stay on
  their true radius and dark arcs buckle.
- **Frequency** is accumulated incrementally (cycles per turn), so the
  *instantaneous* frequency can rise with `darkness` (via `freqMod`) without the
  phase jumping — dark regions wiggle tighter while the path stays continuous.
- **Compress** scales the radial advance, so the pitch shrinks (turns crowd
  together) in dark zones. The `max(0.1, …)` floor keeps the spiral always moving
  outward so it terminates.

All points collect into one `<polyline>` — a single unbroken stroke, ideal for a
pen plotter.

### 5. The rings variant

With **Rings** on, the continuous spiral is replaced by a stack of **closed
concentric rings**. Each ring is walked over a full revolution and emitted as a
`<polygon>`; the inter-ring pitch compresses with the tone sampled at the ring's
start, so dark bands grow denser just as with the spiral. To keep the wiggle
**seamless at the seam**, rings use a fixed integer cycle count per revolution
(`round(frequency)`) — only the wiggle's *amplitude* tracks local darkness, so the
endpoints always meet. `freqMod` therefore has no effect in rings mode.

### 6. Assembly

Everything is emitted into a single grouped element:

```html
<svg viewBox="0 0 W H" width="W" height="H">
  <rect width="W" height="H" fill="#fff"/>           <!-- or #111 when inverted -->
  <g stroke="#111" stroke-width="0.8" stroke-linecap="round" stroke-linejoin="round" fill="none">
    <polyline points="x,y x,y …"/>                   <!-- or <polygon> per ring -->
  </g>
</svg>
```

Coordinates are rounded to one decimal. The whole thing is one self-contained SVG
document string.

## Controls

| Control       | Range     | What it does                                                          |
| ------------- | --------- | -------------------------------------------------------------------- |
| **Pitch**     | 4–30 px   | Base radial spacing between turns/rings (before compression).        |
| **Wobble**    | 0–12 px   | Maximum radial wiggle amplitude in the darkest areas.                |
| **Wiggle**    | 0–40 /turn| Base oscillations per revolution.                                    |
| **Freq mod**  | 0–1       | How much darkness tightens the wiggle on top of the base (spiral only).|
| **Compress**  | 0–0.9     | How strongly dark zones shrink the local pitch.                      |
| **Weight**    | 0.3–2     | Stroke width.                                                        |
| **Contrast**  | 0.5–2.5   | Tone curve before darkness mapping. Higher pushes tones to extremes. |
| **Rings**     | on / off  | Closed concentric rings instead of one continuous spiral.            |
| **Invert**    | on / off  | White line on dark vs. dark line on light; flips which tones buckle. |

## Why deform one path

Building tone from a *single* wound stroke (or a small stack of closed rings)
keeps the output radically simple: one `<polyline>`, no fills, no overlapping
families to reconcile. Driving wiggle and compression from the *same* darkness
value gives a wide tonal range while preserving the unbroken, pen-plotter-friendly
quality of the line — and the centre-out geometry gives results a distinctly
different, optical character from the parallel-line strategies.

## Extending: adding another strategy

See [`README.md`](./README.md) for the full step-by-step. In short: write a pure
`Strategy` in `strategies/`, add it to the `STRATEGIES` array in
`strategies/index.ts`, and document its algorithm in a sibling `*.md` like this
one. It then appears automatically in the picker with its declared controls. A
natural extension here is **multiple focal points** — winding several spirals
from different centres and keeping whichever point is darkest.
